# Contributing

Start with the [shared roadmap](mentor/roadmap.md) and find [your folder](README.md#people).

## Adding notes

Put notes in `mentees/your-name/notes/`. Use a descriptive filename, such as `week-01-notes.md`, `week-01-questions.txt`, or `week-01-handwritten.pdf`. You can use any readable format, in one file or several files.

Add links to your notes in your folder's `README.md` so other people can find them. For a lecture, include its link and useful timestamps. For a paper, include its link and the relevant sections or pages.

Write notes that reflect your own thinking. Short notes are fine. Do not use AI to generate or pad your notes. Do not submit AI-generated summaries as your own work. You can include questions, examples, incomplete arguments, and explanations of what you learned.

## Contributing through GitHub's website

After you receive an invitation to be a collaborator, follow these steps:

1. Open your folder and choose **Add file**, then **Create new file** or **Upload files**.
2. Write or upload your notes. Choose a new branch when you commit the change. Give the branch a short descriptive name, such as `sanika/week-01`.
3. Open a pull request into `main`. Briefly describe what you added. If you want feedback, identify the question or passage and mention the person you want to ask.
4. You can merge your own personal notes without waiting for mentor approval. For changes to another person's notes, ask that person to review first. For substantial changes to shared meeting notes, ask another participant to review. Ask the mentor to review changes to the mentor's roadmap.
5. Delete the contribution branch after merging. Start the next contribution from the current `main` branch.

A pull request proposes a change and gives others a place to comment on it. Publishing your personal notes does not automatically ask everyone to review them.

If you use Git locally, follow the same workflow. Create a short-lived branch from the current `main` branch. Commit your changes, push the branch, and open a pull request. Keep each pull request focused on a small contribution.

## Questions and discussion

Record questions in your notes. To bring a question to the group, open an [issue](https://github.com/ziyang-theory/USRP-UofT/issues) or start a [discussion](https://github.com/ziyang-theory/USRP-UofT/discussions). Include links to the relevant note and source. Use pull request comments for feedback on a proposed change.

Share what you learned and read relevant notes from other mentees. Make specific, constructive comments. Asking someone to explain a step can be as useful as suggesting a correction.

## Sharing files

- Handwritten notes: a PDF or image export is usually easiest for others to read.
- LaTeX: you can share source files, a compiled PDF, or both. Git ignores generated build files such as `.aux` and `.log`.
- Other formats: include a readable export or short instructions to open the file, if needed.

This repository and its conversations are public. Only upload material you intend to share publicly.
