# Contributing

Start with the [shared roadmap](mentor/roadmap.md) and find [your folder](README.md#people).

## Adding notes

Put notes in `mentees/your-name/notes/`. Use a descriptive filename such as `week-01-notes.md`, `week-01-questions.txt`, or `week-01-handwritten.pdf`; any readable format is welcome. You may use one file or several files.

Add links to your notes in your folder's `README.md` so other people can find them. When discussing a lecture, include its link and useful timestamps; for a paper, include the link and the relevant sections or pages.

Notes should reflect your own thinking. Short notes are fine. Do not use AI to generate or pad them, and do not submit AI-generated summaries as your own work. Questions, examples, incomplete arguments, and explanations of what you learned are all welcome.

## Contributing through GitHub's website

Once you have been invited as a collaborator:

1. Open your folder and choose **Add file**, then **Create new file** or **Upload files**.
2. Write or upload your notes. Choose a new branch when committing the change, and give it a short descriptive name, such as `sanika/week-01`.
3. Open a pull request into `main`. Say briefly what you added. If you want feedback, identify the particular question or passage and mention the person you would like to ask.
4. You can merge your own personal notes without waiting for mentor approval. For changes to someone else's notes, ask that person to review first. For substantial changes to shared meeting notes, ask another participant to review; for changes to the mentor's roadmap, ask the mentor.
5. Delete the contribution branch after merging. Start the next contribution from the current `main` branch.

A pull request proposes a change and gives others a place to comment on it. Publishing your personal notes does not automatically ask everyone to review them.

If you already use Git locally, the same workflow applies: create a short-lived branch from the current `main`, commit your changes, push the branch, and open a pull request. Keep each pull request focused on a small contribution.

## Questions and discussion

Record questions in your notes. To bring one to the group, open an [issue](https://github.com/ziyang-theory/USRP-UofT/issues) or start a [discussion](https://github.com/ziyang-theory/USRP-UofT/discussions), linking to the relevant note and source. Use pull request comments for feedback on a particular proposed change.

Share what you learned and read relevant notes from other mentees. Be specific and constructive when commenting; asking someone to explain a step can be as useful as suggesting a correction.

## Sharing files

- Handwritten notes: a PDF or image export is usually easiest for others to read.
- LaTeX: source files and/or a compiled PDF are welcome. Generated build files such as `.aux` and `.log` are ignored.
- Other formats: include a readable export or a short explanation of how to open the file if needed.

This repository and its conversations are public. Only upload material you intend to share publicly.
